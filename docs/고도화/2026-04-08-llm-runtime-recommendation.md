# LLM 런타임 추천과 관측 데이터 활용

## 목적
- 운영 중 쌓이는 observability 메트릭을 단순 저장으로 끝내지 않고, 실제 모델 선택과 병렬도 조정에 활용한다.
- 뉴스 번역, 수동 분석 같은 워크로드별로 “지금 이 머신 상태에서 어떤 모델을 쓰는 게 좋은지”를 설명 가능한 규칙으로 추천한다.

## 현재 구현 범위
- `resource_snapshots`, `execution_metrics`, `hourly rollup`을 기반으로 현재 머신 압박도를 계산한다.
- 시스템 관측 화면에서 아래 항목을 추천 카드로 노출한다.
  - 머신 압박도
  - 뉴스 번역 추천 provider/model
  - 수동 분석 추천 provider/model
  - Ollama 권장 병렬도
- 추천은 `services/llm_runtime_recommendation_service.py`에서 수행한다.
- 추천 결과는 `services/observability_reporting_service.py`에서 observability overview payload에 포함된다.

## 추천 원칙
- 첫 단계는 AI 추천이 아니라 규칙 기반 추천을 사용한다.
- 이유:
  - 왜 그 모델을 추천했는지 설명 가능
  - 운영 중 디버깅이 쉬움
  - 잘못 추천했을 때 threshold 조정이 간단함

## 현재 규칙
### 머신 압박
- `LOW`
  - 메모리/CPU load ratio가 낮고 Ollama RSS가 과도하지 않을 때
- `MEDIUM`
  - 메모리 사용률이 높거나 CPU load ratio가 높을 때
- `HIGH`
  - 메모리 사용률이 매우 높거나 CPU load ratio가 임계치 이상일 때

### 뉴스 번역
- Ollama 사용 중이고 지연 또는 리소스 압박이 높으면 더 작은 모델을 추천
- 지연이 중간 수준이면 `8b 이하` 유지 권장
- 여유가 충분하고 현재 `4b`를 쓰고 있으면 `8b` 업그레이드를 제안할 수 있음

### 수동 분석
- 외부 provider를 쓰는 경우 현재 품질 중심 설정 유지
- Ollama를 쓰는 경우:
  - 압박이 높으면 `8b 이하`
  - 여유가 충분하면 `14b` 계열 권장

### Ollama 병렬도
- 압박이 높으면 `1`
- `4b`급 경량 모델 + 메모리 여유가 크면 `2`
- 그 외에는 `1`

## 왜 이게 도움이 되나
- 뉴스 번역이 느릴 때 단순히 “Ollama가 느리다”가 아니라, 모델 크기/병렬도/머신 압박 중 무엇을 줄여야 하는지 제안 가능
- 수동 분석은 품질 중심, 뉴스 번역은 처리량 중심처럼 워크로드별 운영 정책을 분리할 수 있음
- 나중에 실제 추천과 운영 결과를 비교해 추천 규칙을 개선할 수 있음

## 다음 단계
- 추천 결과를 설정에 바로 반영하는 “적용” 버튼
- 시간대별 정책 분리
  - 장중: 경량 모델
  - 장후/야간: 고품질 모델
- 추천 결과와 실제 성능 변화를 비교하는 피드백 루프
- 규칙 기반 추천 로그를 데이터로 쌓은 뒤 AI 추천기로 확장

## 한계
- 현재는 heuristic 기반이라 모델 품질을 직접 측정하지 않는다.
- Ollama 모델의 실제 다운로드 여부나 로컬 존재 여부는 추천 단계에서 강제 검증하지 않는다.
- GPU/전력/온도 정보는 아직 반영하지 않는다.
