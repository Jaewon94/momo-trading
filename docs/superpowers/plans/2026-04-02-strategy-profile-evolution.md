# 전략 프로필 고도화 계획

작성일: 2026-04-02

## 목적

현재 관리자 `전략` 탭은 `리스크 성향`과 일부 운용 맥락을 설명하는 수준이다.  
하지만 실제 매매 시스템 내부에는 `전략 타입`, `보유 정책`, `리스크 성향`, `주문 처리 방식`이 서로 다른 레이어로 흩어져 있어,
사용자가 "지금 어떤 전략으로 돌아가고 있는지", "새 전략을 어떻게 추가하는지"를 한눈에 이해하기 어렵다.

이 문서는 전략 개념을 `전략 프로필`로 정리하고, 향후 UI/코드 구조를 어떻게 고도화할지 정리한다.

## 현재 문제

1. `리스크 성향`과 `실제 전략 타입`이 같은 것처럼 보인다.
2. 새 전략을 추가하려면 코드 여러 군데를 찾아 수정해야 한다.
3. 관리자 UI에서는 현재 전략 구성이 "한 세트"로 보이지 않는다.
4. 전략 설명은 있으나, 전략을 선택하거나 확장하는 구조는 아직 없다.
5. 종목별 `strategy_type`와 전역 운용 설정 사이의 관계가 명시적으로 드러나지 않는다.

## 목표 상태

전략 관련 설정을 `전략 프로필(strategy profile)` 개념으로 묶는다.

하나의 전략 프로필은 아래 요소를 포함한다.

- 프로필 이름
- 프로필 설명
- 기본 전략 타입 집합
- 기본 리스크 성향
- 기본 보유 정책
- 기본 주문 처리 방식 권장값
- 프로필별 운용 메모

예시:

- `안정 단타`
  - 전략 타입: `STABLE_SHORT`
  - 리스크 성향: `MODERATE`
  - 보유 정책: 당일 청산 우선
- `공격 단타`
  - 전략 타입: `AGGRESSIVE_SHORT`
  - 리스크 성향: `AGGRESSIVE`
  - 보유 정책: 당일 청산 또는 짧은 오버나이트 허용
- `스윙 모멘텀`
  - 전략 타입: 향후 추가
  - 리스크 성향: `MODERATE`
  - 보유 정책: 오버나이트 허용

## 권장 방향

### 1. 전략 프로필 레지스트리 도입

신규 모듈 예시:

- `strategy/profiles.py`

역할:

- 시스템이 지원하는 전략 프로필 목록 정의
- 각 프로필의 표시명, 설명, 전략 타입 구성, 보유 정책, 권장 설정값 제공
- 관리자 UI에 그대로 내려줄 수 있는 단일 소스 역할

### 2. 전략 탭을 "설정 + 설명"에서 "프로필 중심"으로 전환

향후 전략 탭 구성:

- 현재 선택된 전략 프로필
- 프로필별 비교 카드
- 프로필이 실제로 제어하는 값
  - 리스크 성향
  - 보유 정책
  - 주문 처리 방식
  - 대표 전략 타입
- 세부 오버라이드 설정
  - 리스크 성향만 따로 수정
  - 주문 처리 방식만 따로 수정

즉 기본은 프로필을 고르고, 필요하면 세부값을 덮어쓰는 구조가 적합하다.

### 3. 전략 추가 절차를 명시적 프로세스로 단순화

새 전략 추가 시 목표 절차:

1. 새 전략 클래스 추가
2. 프로필 레지스트리에 등록
3. 스크리너/에이전트 라우팅 규칙 연결
4. 관리자 UI에 자동 노출
5. 설명 패널과 문서에서 자동 반영

지금처럼 여러 파일을 암묵적으로 찾아가는 방식은 피한다.

## 단계별 전환 계획

### Phase 1. 문서/설명 정리

목표:

- 현재 구조를 사용자와 개발자가 이해할 수 있게 만든다.
- 전략 탭에서 "리스크 성향은 전략 전체가 아니라 입력값"이라는 점을 드러낸다.

상태:

- 진행 중

### Phase 2. 전략 프로필 레지스트리 도입

목표:

- 코드에서 지원하는 전략 프로필을 한 곳에서 정의한다.

예상 변경:

- `strategy/profiles.py` 추가
- `api/routes/admin.py`에서 프로필 데이터 제공
- 관리자 전략 탭에서 프로필 카드 표시

### Phase 3. 관리자 전략 탭 프로필 선택화

목표:

- `리스크 성향` 단일 셀렉트에서, `전략 프로필` 중심 선택으로 확장한다.

예상 UX:

- 상단: 전략 프로필 선택
- 하단: 프로필 상세 설명
- 고급 설정: 리스크 성향 / 보유 정책 / 주문 처리 방식 오버라이드

### Phase 4. 종목 라우팅과 전략 프로필 연결

목표:

- 종목별 `strategy_type` 선택 로직과 전역 전략 프로필을 일관되게 맞춘다.

예상 변경:

- `stock_screener` 또는 `trading_agent`에서 프로필 기반 전략 매핑
- 신규 전략 도입 시 라우팅 정책 명시화

### Phase 5. 신규 전략 추가 UX 검토

목표:

- 사용자가 UI에서 전략을 "추가"할지, 개발자가 코드로만 추가할지 결정한다.

현재 권장:

- 당장은 코드 기반 추가 유지
- UI에서 임의 전략 생성 기능은 나중 단계에서 검토

이유:

- 자동매매 전략은 설명 카드 추가보다 검증과 안전장치가 더 중요하다.
- 사용자가 UI에서 즉석 전략을 만드는 구조는 현재 시스템 단계에서 과도하다.

## 비권장 방향

- 지금 당장 UI에서 사용자 임의 전략 생성 기능 추가
- `리스크 성향`만으로 전략 전체를 표현하려는 설계
- `strategy_type`를 화면상 라벨만 바꿔서 가리는 방식
- 문서와 코드가 따로 노는 구조
